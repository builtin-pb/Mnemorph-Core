# Memory

Memory gives future work useful understanding without requiring it to reconstruct every past session. Organize it by coherent subject, with the main understanding leading and supporting detail receiving proportionate emphasis. **Intent, Context, Knowledge and Method** overlap: a project can contain a standing preference, changing circumstances, an explanation and an untested procedure together. A useful particular needs neither a general lesson nor its own file. The instance's requirement lists can record its user's intentions for this arrangement.

Provenance governs reliance: human direction supplies authority within its scope; observations supply evidence under their conditions; dates matter to changing context. Examples or failures can carry the main understanding. Their reference role limits instruction selection, not truth or importance. Keep consequential qualifications effective wherever the claim is used.

## Using and revising memory

- [Memory](memory.md) owns organization, discovery, source identity and adoption. Subject accounts can supply knowledge directly as well as inform methods. Use [task history](task-history.md) when bounded native retrieval needs its practical details and known pitfalls.
- The [retrieval contract](retrieval.md) and [budgets and history](budgets-and-history.md) document the memory helpers.
- [Reflect](reflect.md) retains, forgets and revises understanding from sessions and existing memory in coherent subject accounts, permitting deliberate losses. It can identify capability gaps for Learn; retention alone does not demonstrate improvement, and subsequent use tests what a simpler account can sustain. Scheduled and other unattended runs follow [periodic reflection](periodic-reflection.md).
- [Personalize](personalize.md) starts or extends the user's personal memory from sources they offer, audits its coverage and asks for sources an agent cannot reach.

Git can recover committed material, but recovery still depends on recognizing and finding what is missing. A hash identifies bytes without reconstructing them; generated artifacts need sufficient source, dependencies and runtime, while original observations may be irreplaceable. Recoverable forgetting differs from an explicit request to delete history, which supplies no standing permission for later cleanup. A tidy tree alone does not establish successful forgetting.
